# 南枫批量改名项目专属规则

## 扫描与选择

- 只扫描用户指定文件夹的当前层级，只接收普通文件，不递归处理子文件夹。
- 扩展名筛选不区分大小写；“全部”代表不设置任何扩展名限制，不是界面可见标签的并集。
- 新读取的文件默认选中；未选中的行状态为“跳过”，不得进入执行计划。
- 序列/图片与视频标签只是 UI 分组，不改变扫描或执行语义。

## 唯一规则链

所有新文件名必须由 `core/rules.py::apply_rules` 按以下固定顺序生成：

1. 普通查找替换；
2. 删除开头、结尾和指定位置字符；
3. 添加前缀；
4. 添加后缀；
5. 指定位置插入；
6. 自动编号；
7. 扩展名大小写转换。

中间删除使用“位置 + 删除数量”：位置从 1 开始；位置或数量为 0 时不执行中间删除。自动编号只按当前选中项的顺序递增。

## 预览、状态与执行

- 调整数值、文本、勾选项或下拉选项后，预览使用短暂合并刷新，但控件值必须立即、准确变化。
- 预览和执行计划必须消费同一规则链；执行阶段不得重新生成另一套文件名。
- 状态集合：未预览、可改名、未变化、冲突、错误、跳过、已完成、已撤销、失败。
- 批次内目标重名、目标路径已有其他文件、非法 Windows 名称或过长路径均阻止执行。
- 只有“已选择 + 可改名 + 目标路径存在于计划”的行进入 `RenamePlan`。
- 执行前必须显示确认；冲突或错误存在时，执行按钮禁用。

## 撤销与日志

- 每批先将全部源文件改为同目录唯一临时名，再写入最终目标名；仅大小写变化和名称互换也走同一路径。
- 任一阶段失败时，全部已移动文件先进入独立回滚临时名，再恢复原路径，不允许保留部分成功。
- 回滚不完整时写入 `logs/recovery_*.json`，记录原路径、当前路径、目标路径和错误，并在界面明确提示。
- 每次执行写入独立 JSON 日志；只有完整成功批次才写入 `logs/last_undo.json`。
- 撤销复用相同事务流程，不依赖逐项反序改名。
- 只有最近一次成功批次可撤销；完整成功撤销后清空可撤销项，防止重复执行。
- 日志是诊断与恢复证据，不进入 Git，不写账号、密钥或外部服务数据。

## UI 合同

- 第一屏是工作台：左侧入口与流程、顶部来源设置、动作条、中央文件表、右侧规则链、底部固定状态区。
- 表格标题和单元格居中；自由文本输入框文字居左；左侧“快捷入口/操作流程”分组标题居左。
- 原文件名和新文件名是主要比较列，必须优先获得横向空间；主表不得依赖水平滚动条才能完成主要比较。
- 规则区域按查找、添加、删除、编号、扩展名分组，每组保留独立重置；总重置同时保留。
- 数字控件单击一次只变化一次；长按延迟后连续变化；快速点击次数与数值变化严格一致。
- 文件名相关表头使用自然数字排序，支持反复点击切换正序/倒序。
- 原文件名、新文件名、扩展名和所在目录支持点击复制；提示使用预留状态区、按来源着色并自动消失。
- 选择列支持按下并拖动连续勾选或取消；选择状态和业务状态保持分列。
- 主窗口按当前屏幕的 Qt 逻辑可用区域等比缩放；字号、控件、图标、边距、规则栏和表格列宽使用同一比例。
- 左侧标题、分组和流程文字保持单行，缩放后必须用实际字体宽度检查，不得换行、省略或裁切。
- 跨显示器时必须从基准尺寸重新计算，禁止在上一次结果上继续乘比例。

## 项目边界与风险

- 不处理文件夹、递归目录和跨磁盘移动。
- 不提供多级撤销；回滚不完整时提供恢复清单，但没有自动恢复向导。
- 没有代码签名、SmartScreen 和全新机器验收。
- 高 DPI 已完成逻辑尺寸与离屏渲染验证；真实双显示器、Windows 辅助技术和不同缩放屏幕间拖动仍需人工验收。
