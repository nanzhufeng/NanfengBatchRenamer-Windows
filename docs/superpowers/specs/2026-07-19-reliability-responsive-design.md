# 可靠执行与等比缩放设计

## 范围

本轮只处理四项已确认风险：Windows 仅大小写改名、批次部分失败恢复、大批量性能基线、高 DPI/多显示器/低分辨率与无障碍。业务规则顺序、产品结构和发布方式不变。

## 执行事务

1. 执行前再次校验所有源路径、目标路径和批次目标唯一性。
2. 每个源文件先改为同目录唯一临时名，解决大小写改名和名称互换占用。
3. 全部进入临时阶段后，再逐个改为最终目标名。
4. 任一阶段失败，按反序将已移动文件恢复到原路径。
5. 回滚全部成功时，本批次没有成功项，也不覆盖最近一次可撤销记录。
6. 回滚仍有失败时，写入恢复清单，记录原路径、当前路径、目标路径、阶段与错误；界面明确提示需要人工恢复。
7. 完整成功后才写入最近一次撤销记录。

## 等比缩放

- 设计基准为 `2200 × 1152` 可用区域；根据当前屏幕可用几何计算统一缩放系数。
- 字号、控件尺寸、图标、间距、边距、侧栏、规则栏、表格行高和列宽使用同一系数，不单独锁定字号。
- 标题、按钮和分组标签保持单行。侧栏宽度同时满足等比宽度与最长文字实际宽度，防止像素取整造成裁切。
- 启动、窗口显示和跨显示器移动后重新读取当前屏幕；只在屏幕或可用区域变化时重新应用，避免缩放抖动。
- 主方案不折叠。仅当可用区域低于 `1280 × 720` 且等比缩放后仍无法完整显示时，允许将未启用规则作为备用折叠对象。
- Windows DPI 由 Qt 高 DPI 机制处理；应用只根据 Qt 提供的逻辑可用区域缩放，避免重复缩放。

## 性能与可观测性

- 生成纯内存 `1,000 / 10,000 / 50,000` 条规则与预览样本，不接触用户目录。
- 分别测量规则计算、预览冲突检查与自然排序；结果写入 JSON，包含 Python/平台信息、样本量、耗时和吞吐。
- 默认性能检查使用宽松的机器相对阈值，防止数量级回退，不把单次峰值当作优化完成。
- UI 表格只做较小规模离屏刷新基线，避免测试本身长时间占用桌面资源。

## 无障碍

- 主要按钮、路径输入、扩展名筛选、规则开关、数字输入、表格和状态区提供可访问名称或描述。
- 保留原生 Tab 顺序和焦点样式；自定义数字箭头提供上调/下调名称。
- 状态不能只依赖颜色，继续保留中文状态文字和问题提示。

## 验收矩阵

- 分辨率：`1280×720`、`1366×768`、`1600×900`、`1920×1080`、`2200×1152`。
- Windows 缩放：`100%`、`125%`、`150%`、`175%`；自动测试验证逻辑尺寸，真实缩放等级分开报告。
- UI 断言：无文字换行/裁切、无主窗口横向滚动、主要对比列保留、右侧规则完整、可访问名称存在。
- 文件事务：普通批次、仅大小写、名称互换、临时阶段失败、最终阶段失败、回滚成功、回滚失败恢复清单。

## 停止条件

核心与 UI 合同测试、源码编译、性能基线和离屏分辨率矩阵通过后停止。本轮不打包、不发布、不操作用户真实文件；真实 Windows DPI、多显示器和辅助技术验收单独报告其完成等级。
